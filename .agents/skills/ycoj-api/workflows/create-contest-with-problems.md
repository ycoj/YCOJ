# Create a contest with selected problems

This sequence uses the server’s existing problem search and contest form handlers. Keep the returned domain and document IDs; do not guess IDs or POST to a `postXxx` suffix.

1. Resolve the base URL, target domain, contest title/content, intended schedule and timezone, and an authorized `sid`. The account needs `PERM_CREATE_CONTEST` (plus configured domain privileges). The server interprets `beginAtDate` and `beginAtTime` in the authenticated user's configured `timeZone`; if that is not the intended timezone, convert the wall time or correct the profile before writing. Send `GET /contest/create` in the target domain to confirm available rule/default data.
2. Search candidates with `GET /p?q={encoded title}&limit=50&page=1&quick=true` in the target domain. This is candidate search, not an exact-title predicate: complete every result page, then fetch `GET /p/{pid}` and require `pdoc.title === suppliedTitle` locally. Disambiguate duplicates using `pdoc.tag`, `pdoc.content`, `pdoc.reference` (when present), and the returned owner `udoc`; retain the selected numeric `pdoc.docId`. Never choose from fuzzy title similarity alone.
3. Build `pids` as the newline/comma content accepted by `Types.Content` (the frontend form serializes the selected numeric IDs). Example fields: `{ beginAtDate:"2026-09-01", beginAtTime:"10:00", duration:120, title:"Weekly Contest", content:"...", rule:"oi", pids:"1001\n1002", rated:false, autoHide:false, allowViewCode:false, allowPrint:false, keepScoreboardHidden:false, langs:["cc.cc17"] }`.
4. Submit `POST /contest/create` with those fields and `Content-Type: application/json` (or the browser form encoding). Success in JSON negotiation is `{ "tid":"665f00000000000000000001", "url":"/contest/665f00000000000000000001" }`; normal browser negotiation follows the handler redirect to that URL. Fetch the returned detail/problem list and verify `tdoc.pids` contains exactly the intended IDs. A validation error means the request was not created; stop and correct the named field.
5. If verification shows the wrong problem, stop submissions and use `POST /contest/:tid/edit` with the corrected full field set. Re-fetch `GET /contest/:tid/problems`; stop only when title, rule, schedule, and selected problem documents match the pre-submit checklist.
